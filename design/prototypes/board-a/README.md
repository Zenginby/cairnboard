# Board A

Classic token-sized columns keep each workflow stage visible while scrolling horizontally within the board on desktop. Phones show one column at a time with the approved segmented-pill treatment; sticky headers retain counts and an inline add form.

- Preview: `npm run design:serve`, then `http://127.0.0.1:4391/prototypes/board-a/`. `?project=ornek-proje` starts with a project filter.
- Motion: pointer moves settle with visible-card FLIP using `--motion-duration-fast` and `--motion-ease-settle`, followed by the shared opacity highlight. The source stays at 40% opacity and a token-derived 2px line marks insertion. Only transforms and opacity animate; reduced motion removes settling and keeps short fades. A drag ghost follows direct pointer input without a transition, including in reduced motion.
- Keyboard: `M` on a focused card opens **Taşı…**; arrow keys, Home and End navigate that menu, `Escape` cancels, and Tab closes it. The menu supports adjacent reordering and the top/bottom of every configured column. Each move restores card focus and announces its source, destination and position through one persistent status region. `C` opens the active column's inline form; `N`, `/`, `?` open quick note, search and help. arrow keys, Home and End switch focused mobile column tabs.
- Touch: drag the dotted handle; dragging elsewhere on a card leaves native vertical scrolling available. **Taşı…** is also a single-pointer alternative. Dragging supports edge scrolling and Escape/pointer-cancel cleanup.
- Prototype controls: full, empty, loading, failed, claimed, 409 conflict, long text and exactly 300 cards in one column. Filters combine; moves update the backing order so filtering does not undo them. Fixture changes reset in-memory edits and claimed/300-card fixtures clear filters to expose the scenario.
- Limits: fictional, per-page memory only; no Markdown writes, cross-page persistence or real conflict detection. The eight project tones and column roles come from the local fixture plus shared sample. The 300-card view uses content visibility, delegated pointer handling, observed visible cards for FLIP/drag targeting, and a single reusable move menu; it does not virtualize the DOM.
- Proposed shared change: extend `moveCard` with insertion positions, visible-only FLIP, full announcements and card focus. Add a pointer-drag helper that preserves native touch scrolling. The local implementation avoids changing the approved shared components. No new design token was needed; the column width is 296px from spacing tokens.
